## 1. 产品目标与使用场景

### 1.1 一句话定位
把朋友 **马泽杰**（广东石油化工学院 物联网工程，本科在读）包装成「AI · 计算机视觉 · 全栈」方向的应届求职者，一屏之内让 HR 看到他是谁、做过什么、为什么值得约面试。

### 1.2 目标
| 目标 | 度量方式 |
|---|---|
| HR 在 **10 秒内** 看到姓名、学校、方向、一句话亮点 | 视觉层级 + Hero 文案 |
| HR 在 **30 秒内** 看到 2 项核心成果（YOLO 论文 / 两个自建站） | Hero 下方的 Work 摘要 |
| HR 在 **60 秒内** 能顺着 "工作流 / 奖项 / 关于我 / 联系方式" 走完一遍 | 顶部导航 5 个锚点 |
| 投简历时直接把网站链接附在简历上 | 站点有 OG 卡片、可分享链接 |

### 1.3 使用场景
- 场景 A：HR 收到简历 → 顺手点开网站 → 30 秒看完 → 决定约面试。
- 场景 B：HR 直接在搜索引擎/招聘平台看到链接 → 进来直接看亮点。
- 场景 C：朋友本人发给别人 "这是我的作品集"。

### 1.4 非目标（第一版不做）
- 不做登录、不做评论、不做留言板。
- 不做博客 / 文章系统。
- 不做线上简历下载（HR 已经有 PDF）。
- 不做多语言切换器（中文为主，少量英文 subtitle 直接写死在组件里）。
- 不做公网部署（先本地预览）。

## 2. 整体页面框架与导航结构

### 2.1 形态
**单页滚动（SPA + 锚点导航）**。不切路由、不做二级页。原因：参考站本身就是单页，HR 不会点进二级页找内容。

### 2.2 顶部导航
固定在视口顶部，半透明深色背景，滚动时增强模糊。

| 项 | 类型 | 文案 |
|---|---|---|
| 左 | Logo | 圆形字母组合 `MZ`（马泽杰拼音首字母），点击回到顶部 |
| 中 | 锚点链接 | Home / Work / Honors / About / Contact |
| 右 | 状态徽章 | `Available for · 2026 校招`（圆点 + 文字，点击可触发联系区块） |

### 2.3 页面分区（自上而下）
1. **Hero** — 名字、tagline、简介、CTA
2. **Work** — 2 个核心项目卡片
3. **Honors** — 5 项奖学金
4. **About** — 性格标签 / 兴趣 / 关键词 / 螺旋照片展
5. **Contact** — 邮箱 / 城市 / 社交 / 联系电话 + Contact 按钮
6. **Footer** — 版权 / 最后更新时间

## 4. 各模块用途

### 4.1 Hero
- **用途**：3 秒定生死。把"我是谁 + 做什么 + 水平如何"塞进一屏。
- **第一版最必要的数据**：name / tagline / summary / 两个 CTA。
- **第一版最必要的操作**：点击 CTA 平滑滚动到对应区块。

### 4.2 Work（项目/作品）
- **用途**：让 HR 看到他「真的能做出东西」，不是只写论文。
- **第一版卡片内容**：项目封面占位图（可空） + 标题 + 时间段 + 1~2 句核心亮点 + 技术栈 chips + "查看详情"（第一版：弹窗或锚到下方内联详情，不做新页面）。
- **第一版要放的项目**（来自简历）：
  1. `aigcdown.com` — 独立开发的降论文 AIGC 率网站（2026.05 - 至今）
  2. `jinengcang.cn` — "技能仓"在线课程平台（2026.08 - 至今，目前 50+ 用户）
  3. `YOLO-lychee-advanced` — 基于改进 YOLOv11 的荔枝虫眼检测（2025.03-05，SCI 二区，DOI 10.3389/fpls.2025.1643700）
  4. `YOLO-lychee-anthracnose` — 基于改进 YOLOv12 的荔枝炭疽病轻量化分级（2025.06-08，SCI 二区，DOI 10.3389/fpls.2025.1688675）

> 第一版先放 2 个最硬的项目卡片（两个自建站，因为带链接 + 用户量更有说服力），论文作为"科研"分区放在 Honors 下面或作为轻量"Publication"分组（见 4.3）。

### 4.3 Honors（奖项 + 论文）
- **用途**：权威背书。
- **第一版内容**（按时间倒序）：
  - 一等奖学金
  - 校级三好学生
  - 国家励志奖学金
  - 吴飞鹏奖学金
  - 肇英集团奖学金
- **第一版要不要放论文**：**要**，放在同一区块下、作为"Publication"子分组：
  - 2 篇 SCI 二区论文标题 + 期刊缩写（Frontiers in Plant Science）+ DOI 链接

### 4.4 About（关于我）
- **用途**：从能力到人格的补充。
- **第一版结构**（左侧文字 / 右侧螺旋照片展）：
  - **左**：
    - 中文大标题 `关于我`
    - 2~3 句自我介绍（占位：`热爱用 AI 与代码解决问题，喜欢把论文里的算法变成可被真实用户用上的产品。`）
    - 性格 chips（5 个）：`Curious` / `Calm` / `Precise` / `Creative` / `AI 驱动`
    - 兴趣（2~3 个关键词）
    - 技能关键词（10~15 个，chips）：`Python` / `Linux` / `PyTorch` / `YOLO` / `Next.js` / `React` / `TypeScript` / `Docker` / `PostgreSQL` / `Drizzle` / `AI Agents` / `LoRA` / `Nginx` / `Caddy`
  - **右**：**螺旋照片展**（参见 4.4.1）

#### 4.4.1 螺旋照片展（第一版）
- **结构**：6 个槽位，围成一条沿 Z 轴螺旋上升的轨道，鼠标拖拽 / 滚轮可旋转。
- **槽位内容字段**：`{ src, caption, category }`，`src` 缺失时显示占位 SVG（暗色 + "PHOTO 01" 字样）。
- **交互**：
  - 鼠标悬停 → 该卡片放大 + 底部显示 caption + category
  - 拖拽 → 旋转整条轨道（framer-motion 或自写 `requestAnimationFrame`）
  - 触屏滑动 → 同样支持
- **退化方案**：`prefers-reduced-motion: reduce` 时不自动旋转，只允许点按切换。
- **第一版 6 张占位图**：用程序生成（SVG 渐变 + 大字号 01~06）写入 `public/images/photos/`，不联网拉图。

### 4.5 Contact
- **用途**：让 HR 30 秒内决定怎么联系。
- **第一版结构**（参考站同款三列 + 按钮）：
  - **EMAIL**：`hassanishaq208@gmail.com`（可点复制）
  - **LOCATION**：`杭州 / 中国`（或"广东 茂名"—— 见 §11 待确认）
  - **SOCIAL**：GitHub / 掘金 / 知乎 / B站（链接先留空，徽标灰显 + tooltip "待补"）
  - 底部一句中文 + 右侧 `Contact` 圆角按钮（点了 = 复制邮箱）
- **手机号字段**：数据结构里保留，第一版页面**不展示**（保护隐私；HR 已有 PDF 简历）。

### 4.6 Footer
- 一行：`© 2026 马泽杰 · 杭州 / 中国 · 最后更新 2026-09-01`
- 右侧：`Built with Vite + React + ❤️`（可选，第一版可省）

## 5. 第一版各模块最必要的数据与操作

> 所有数据集中在 `src/data/*.json`，由 `src/lib/data.ts` 统一读取，组件不直接 import JSON（便于以后接 CMS / 后端）。schema 在 `docs/data-schema.md` 单独写（开发计划阶段产出）。

| 模块 | 必要数据 | 必要操作 |

> **用户已决定**：联系方式字段（邮箱/微信/手机号/社交链接）**全部预留位置**，先不填具体值（邮箱已知 `hassanishaq208@gmail.com` 可先填），其它留 `null` + 灰显徽标。

## 7. 本地数据文件、备份与恢复

### 7.1 数据文件清单（全部在 `src/data/`，JSON UTF-8 无 BOM）
| 文件 | 用途 | 谁来改 |
|---|---|---|
| `profile.json` | 名字、tagline、简介、CTA 文案 | 用户 |
| `nav.json` | 导航条目 | 用户 |
| `projects.json` | 项目列表 | 用户 |
| `honors.json` | 奖项列表 | 用户 |
| `publications.json` | 论文列表 | 用户 |
| `about.json` | 自我介绍 / 性格 / 兴趣 / 技能 | 用户 |
| `photos.json` | 螺旋照片展槽位 | 用户 |
| `contact.json` | 邮箱 / 城市 / 社交 / 手机（隐私字段） | 用户 |

### 7.2 备份
- **自动备份**：每次 `npm run content:edit <file>` 改 JSON 时，在 `_backup/YYYY-MM-DD/<file>.json` 留一份最近一版（保留最近 7 天，旧的自动清理）。
- **手动备份**：`npm run backup` → 把整个 `src/data/` + `public/images/` 打包到 `_backup/manual-YYYYMMDD-HHmm.zip`。
- **改之前必看**：`scripts/validate-data.mjs` 在每次 `dev`/`build` 启动时跑一遍 schema 校验，错就拒绝启动 + 提示哪个字段有问题。

### 7.3 恢复
- `_backup/` 里的备份都带时间戳，丢哪个就 `cp` 回来。
- 如果用户想"回到上个月版本"——告诉他备份目录在哪，他选一个，我帮他恢复（不擅自恢复）。

### 7.4 重要原则
- **不删任何文件除非用户明确说"可以删"**。
- **不连真实数据库**。所有数据 = JSON，源码即数据库。
- **图片 = 静态文件**。放在 `public/images/`，文件名用英文/拼音。
- **隐私字段（手机号/微信号）默认不渲染到 DOM**，仅存在 JSON 里。

### 11.1 内容占位原则（2026-09-02 补充，用户明确要求）

**这个项目目前只搭框架。凡是简历原文里没有的细节，一律留空显示「待补充」，不许编。**

| 内容 | 来源 | 状态 |
|---|---|---|
| 奖项名称（5 项） | 简历原文 | ✅ 真实 |
| 奖项的颁发单位 / 级别 / 年份 | 简历里没有 | ⏳ **留空，等本人提供** |
| 自我介绍（About bio） | 我起草的占位 | ⏳ 等本人提供 |
| 性格标签 / 兴趣 | 我起草的占位（参考站风格） | ⏳ 等本人提供 |
| 技能关键词（15 个） | 简历原文 | ✅ 真实 |
| 教育信息 + 主修课程 | 简历原文 | ✅ 真实 |
| 2 个项目的内容 | 简历原文 | ✅ 真实（措辞可再润色） |
| 2 篇论文信息 + DOI | 简历原文 | ✅ 真实 |
| 邮箱 | 简历原文 | ✅ 真实 |
| 城市 | 简历里没有 | ⏳ 留空 |
| 手机 / 微信 / 社交链接 | 简历部分有 / 大多没有 | ⏳ 留空 |
| 6 张照片及说明 | 无素材 | ⏳ 留空 |

> 等你把朋友的详细素材（奖项细节、自我介绍、照片、社交账号）发我，我按槽位填进去就行，框架不用动。

## 12. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 螺旋照片展在低端机掉帧 | 中 | `prefers-reduced-motion` 降级 + transform 走 GPU 合成层 |
| 中文 Web 字体加载慢 | 中 | 字体走系统字体栈 + 只在标题用思源宋体（用 woff2 + preload） |
| 视频/参考素材被误删 | 低 | 所有素材只在 `_ref/`，标记为参考，不进构建；删之前我先跟你确认 |
| 用户改了 JSON 后页面没刷新 | 低 | `vite-plugin-restart` 或在 README 写清"改了 JSON dev server 会热重载" |
| 玻璃方碑在 Safari 不动 | 中 | 全部用 `backdrop-filter` 标准语法 + 兜底纯色 |
